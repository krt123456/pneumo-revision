# Fasih: in-app AI chat with the learner's own API key ("وضع API") — implementation spec v1

Fasih is an Android app (WebView + vanilla JS SPA in `www/`) that teaches English to an Arabic speaker (A2 → C1, IELTS). UI language: Arabic, RTL. Read `www/js/core.js`, `ui.js`, `flows.js` (the `Runner` class) and `www/css/app.css` first and follow their style: `'use strict'`, one IIFE `(function (F) { ... })(window.Fasih)`, no frameworks, no build step, template strings + `F.esc()` for every dynamic value, the existing CSS variables for both themes.

## What you build
A chat screen inside Fasih for learners who have an API key for Claude (Anthropic), ChatGPT (OpenAI), Gemini (Google) or Grok (xAI). Text + photos, streaming replies, model picker, saved conversations. When a reply contains a "Fasih pack" (a JSON code block the tutor module knows how to import) the chat shows an import card instead of raw JSON.

## Native transport (implemented in Java by someone else; `F.nat(name, ...args)` returns `undefined` in a browser)
- `aiKeys()` → JSON string `{"claude":true,"chatgpt":false,"gemini":false,"grok":false}`: which providers have a saved key. The key itself never reaches JavaScript.
- `askAiKey(provider)` → opens a native dialog where the learner types, pastes or deletes his key. Event `aikey` `{ p, has }` after a change.
- `aiHttp(json)` with `json = JSON.stringify({ id, p, method, path, body, stream })`: `p` = provider key; `method` `'GET'` or `'POST'`; `path` must match `^/v1(beta)?/[A-Za-z0-9_.:/-]+(\?[A-Za-z0-9_=&.-]*)?$`; `body` = a JSON string (POST only); `stream` boolean. Host and authentication are fixed natively per provider and cannot be set from JS:
  claude → `https://api.anthropic.com` (`x-api-key`, `anthropic-version: 2023-06-01`) · chatgpt → `https://api.openai.com` (`Authorization: Bearer`) · gemini → `https://generativelanguage.googleapis.com` (`x-goog-api-key`) · grok → `https://api.x.ai` (`Authorization: Bearer`). POST always carries `content-type: application/json`.
  Inside `body`, every token `@@IMG:<id>@@` is replaced natively by the base64 JPEG data of photo `<id>` (ids come from `F.img.pick`, see `core.js`). So an image part is written e.g. `"data":"@@IMG:17@@"` or `"url":"data:image/jpeg;base64,@@IMG:17@@"`.
- Event `http`: `{ id, ev: 'open', status }` → `{ id, ev: 'data', text }` zero or more times (pieces of the response body that may be cut ANYWHERE, even in the middle of a line or of a multi-byte sequence boundary already decoded: buffer and split on `\n` yourself) → `{ id, ev: 'done' }`; or `{ id, ev: 'error', status, body }` (`status` 0 = no network / timeout; `body` = the provider's error text, max 4 KB, or an exception message).
- `aiHttpCancel(id)`.
`F.on(type, fn)` keeps ONE handler per event type: register a single `http` handler and a single `aikey` handler in `chat.js` and dispatch by `id`.

Wrap all of this in `F.chat.transport = { keys() → object, askKey(p), http(req, { open, data, done, error }) → cancel() }`. The default transport uses the bridge when `F.isApp`; the tests replace it with a mock. In a plain browser without a mock, API mode is unavailable: `F.chat.available()` is false, `F.chat.ready()` is false, and `F.chat.keys()` / `F.chat.open()` show a sheet "وضع API متاح في تطبيق الأندرويد فقط."

## Provider adapters (`F.chat.providers[k]`)
Each adapter: `models: { path, parse(json) → [{ id, name, at? }] }`, `chat: { build(model, system, msgs) → { path, body } , delta(obj) → string, error(obj) → string|null }` where `obj` is one parsed SSE `data:` JSON object. `msgs` = `[{ role: 'user'|'assistant', text, img? }]`.
VERIFY every format below against the official documentation before writing the adapter (use web search / fetch: docs.claude.com or platform.claude.com/docs, platform.openai.com/docs, ai.google.dev/api, docs.x.ai) and report anything that differs or that you could not confirm:
- claude: `GET /v1/models?limit=100` → `data[].id`, `display_name`, `created_at`. Chat `POST /v1/messages` `{ model, max_tokens: 4096, system, stream: true, messages: [{ role, content: [{ type: 'text', text }, { type: 'image', source: { type: 'base64', media_type: 'image/jpeg', data } }] }] }`. Stream: `content_block_delta` with `delta.type === 'text_delta'` → `delta.text`; `type === 'error'` → `error.message`.
- chatgpt: `GET /v1/models` → `data[].id`, `created`. Chat `POST /v1/chat/completions` `{ model, stream: true, messages: [{ role: 'system', content }, { role, content: string | [{ type: 'text', text }, { type: 'image_url', image_url: { url: 'data:image/jpeg;base64,…' } }] }] }` (send no max-token parameter). Stream: `choices[0].delta.content`; the literal line `data: [DONE]` ends it.
- grok: the same wire format as chatgpt, `GET /v1/models`, `POST /v1/chat/completions`.
- gemini: `GET /v1beta/models?pageSize=200` → `models[]` with `name` (`models/<id>`), `displayName`, `supportedGenerationMethods` (keep those that include `generateContent`). Chat `POST /v1beta/models/<id>:streamGenerateContent?alt=sse` `{ system_instruction: { parts: [{ text }] }, contents: [{ role: 'user'|'model', parts: [{ text }, { inline_data: { mime_type: 'image/jpeg', data } }] }] }`. Stream: `candidates[0].content.parts[].text`; a blocked prompt shows in `promptFeedback.blockReason`.
Model ids in `path` must satisfy the path pattern above (reject others with a clear message). NEVER hardcode a default model id: they go stale. Model list: drop non-chat models heuristically (ids containing embed, tts, whisper, audio, realtime, transcribe, moderation, image, dall-e, imagen, veo, sora, aqa, computer-use…), newest first when the API gives a date, else id descending.

## State (already in `core.js` DEF)
`S.chat = { model: {}, cur: null, convs: [] }`. `model[k]` = chosen model id per provider. `convs` = `[{ id, ai, title, at, sys, msgs: [{ role, text, img?, at, err?, imp? }] }]`, newest first; keep ≤ 12 conversations, ≤ 80 messages each, and ≤ 400 000 characters of text in total (drop the oldest conversations first, never the current one). Never store image data, only ids; photos live in a cache and may disappear (an `<img>` that fails to load is hidden). Save with `F.save()`; older saved states may lack `S.chat` (guard).
Which provider: `S.tutor.ai` (set by the tutor page; if it is `'other'` or missing use `'claude'`).

## Public API (the tutor module calls these; keep the names)
`F.chat.available()` · `F.chat.ready(ai)` → a key is saved for that provider · `F.chat.keys()` → the keys sheet · `F.chat.open()` → the chat screen on the current conversation (or an empty new one) · `F.chat.start({ title, system, user, img })` → new conversation with that system prompt, sends `user` (with photo `img` if not empty) at once · `F.chat.close()` · `F.chat.md(text)` → safe HTML.
You call the tutor module (it may be missing or unfinished while you work: always guard, and stub it in your tests when absent): `F.tutor.system()` → system prompt for a free chat (fallback when absent: a short built-in prompt: personal English tutor for an Arabic speaker aiming at C1 / IELTS 7, explain in simple Modern Standard Arabic, examples in English, correct mistakes honestly) · `F.tutor.offer(text)` → `{ ok: true, pack }` when the reply contains a Fasih pack · `F.tutor.preview(pack, onDone)` → opens the approval sheet; `onDone(true)` when imported.

## Chat screen
A full-screen overlay appended to `document.body` (same idea as `.run` in `flows.js`; reuse the existing colour variables, safe-area paddings and the look of the app). While it is open set `F.runner = { askClose() { F.chat.close(); }, close() { F.chat.close(); } }` and restore `null` on close: the Android back button and the app's re-render logic already respect `F.runner`. Call `F.nat('keepAwake', true/false)` like the Runner does. After closing, call `F.render()`.
- Header: ✕, title "{Provider} · {model}" (tap → model picker), menu ⋮ with "محادثة جديدة", "المحادثات السابقة" (list sheet; tap to reopen, with delete), "🔑 المفاتيح".
- Messages: learner bubbles on one side, tutor on the other, `dir="auto"` per paragraph so Arabic and English lines align correctly; code blocks LTR in a scrollable box. Auto-scroll to the bottom while streaming unless he scrolled up. A request-started conversation shows its first message as a compact card (the `title` plus `<details>` with the full text).
- Tutor message rendering = `F.chat.md`: escape EVERYTHING first, then only: paragraphs and line breaks, `**bold**`, `*italic*`, inline code, fenced code blocks, `-`/`*`/`1.` lists, `#` headings (as bold lines), `---`. Markdown links render as plain text "label (url)" with no anchor element. Tables stay as preformatted text. Nothing from the model may ever become an HTML tag, attribute or URL.
- Fasih pack: after a tutor message finishes, call `F.tutor.offer(text)`; when it returns a pack, render the message without the pack's code block and add a card "📦 حزمة فصيح: {pack.title}" with the button "راجعها وأضفها" → `F.tutor.preview(pack, ok => …)`; after import mark the message `imp: 1` and show "أُضيفت ✓" instead of the button. While streaming, as soon as an unterminated code fence that contains `"fasih"` starts, hide that partial block behind a line "… يجهّز المعلّم حزمة فصيح".
- Under each finished tutor message: 📋 نسخ (`copyText` / clipboard) and 🔊 استمع (reads the English lines of the message with `F.tts.speak`, skipping lines that are mostly Arabic; tap again to stop).
- Composer: auto-growing `<textarea dir="auto">`, 📷 (only when `F.img.ok()`: small menu "التقط صورة" / "من المعرض" → thumbnail chip with ✕ above the composer), 🎤 (only when `F.stt.ok()`: English dictation with `F.stt.start`, appends the recognised text), send ➤ which becomes stop ■ while a reply streams (`cancel()`; keep the partial text).
- First use for a provider with no stored model: open the model picker before sending (keep the pending message and send it once a model is chosen). Picker sheet: search box, list (name + id), a free-text field "أو اكتب معرّف النموذج", hint "الأحدث في الأعلى. النماذج الأصغر (mini، flash، haiku) أرخص وأسرع وتكفي للتصحيح اليومي." Loading and error states.
- Request building: history = the conversation's messages, capped to the last 40 and 80 000 characters (always keep the first one); photos are sent only for the two most recent photo messages, older ones become the text "[photo no longer attached]". Errors appear as an inline bubble with a retry button and a clear Arabic line by status: 401/403 "المفتاح غير صحيح أو لا يملك صلاحية هذا النموذج." (+ button "🔑 المفاتيح") · 404 "هذا النموذج غير متاح لمفتاحك. اختر نموذجاً آخر." (+ model picker) · 429 "بلغتَ حدّ الاستعمال أو انتهى رصيدك لدى {Provider}." · 400 "رفض {Provider} الطلب." · 5xx/529 "خدمة {Provider} مشغولة الآن. أعد المحاولة بعد قليل." · 0 "لا اتصال بالإنترنت أو انتهت المهلة." Always add the provider's own message in a small `dir="ltr"` line.
- Keys sheet: one row per provider (name, "محفوظ ✓" or "لا مفتاح", button "أضف" / "غيّر" → `transport.askKey`), refresh on the `aikey` event, and this text: "تكتب المفتاح في نافذة خاصة خارج صفحة التطبيق. يُحفظ مشفّراً في هاتفك ولا يُرسل إلا إلى خوادم الشركة صاحبته. فصيح لا يملك خوادم ولا يرى محادثاتك. الاستعمال يُحسب على رصيدك لدى الشركة، وهو منفصل عن اشتراك تطبيقها." Plus where keys are created, as buttons opening the provider's console with `F.openUrl` (verify the current URLs in the docs).
- Empty state of a new free chat: a short welcome and 4 suggestion chips in Arabic (e.g. "صحّح هذه الجملة: …", "اشرح لي الفرق بين …", "حاورني بالإنجليزية عن يومي", "اختبرني في كلماتي الأخيرة") that fill the composer.
Looks: test at 360×760 and 390×844, light and dark (`document.documentElement` theme handling is in `ui.js` `applyTheme`), with long Arabic + English mixed replies, a long code block, and the on-screen keyboard case (composer must stay visible: the activity uses `adjustResize`, so plain flex layout with `height: 100%` works; do not use `100vh` tricks that break when the keyboard opens).
